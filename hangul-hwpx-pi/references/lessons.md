# 한글(hwpx)·한컴 자동화에서 겪은 것들

2026년 11월, 한컴오피스 한글 2020(appVersion 11)이 있는 Windows 11에서 60쪽 넘는 학술 논문(표 26개, 각주 31개, 수식, 코드 상자, 목차)을 열 번 넘게 고치며 확인한 내용이다. 다른 판의 한글에서는 값이 다를 수 있으니, 숫자는 렌더해서 다시 확인한다.

## 파일 구조

- hwpx = zip. 본문 `Contents/section0.xml`(구역마다 하나), 모양 `Contents/header.xml`, 판 정보 `version.xml`. 다시 쓸 때 **zip 항목 순서와 압축 방식을 그대로** 둔다.
- 문단 `hp:p` → `hp:run`(charPrIDRef) → `hp:t`. 줄바꿈·탭은 `hp:t` 안의 자식 요소(`hp:lineBreak`, `hp:tab`)이고 뒤 글은 그 요소의 tail.
- 표·글상자·그림은 본문 문단의 run 안 요소(`hp:tbl`, `hp:rect`, `hp:pic`). 표 칸 `hp:tc` > `hp:subList` > `hp:p`.
- 각주: run 안에 `…글</hp:t><hp:ctrl><hp:footNote number="n" instId="…"><hp:subList><hp:p><hp:run><hp:ctrl><hp:autoNum num="n" numType="FOOTNOTE"/></hp:ctrl><hp:t> 각주 글</hp:t>…</hp:ctrl><hp:t/>`.
  번호는 footNote@number와 autoNum@num 두 곳. 넣거나 지우면 문서 순서대로 둘 다 다시 적는다. instId는 문서 안에서 겹치면 안 된다.
- 고친 문단의 `hp:linesegarray`(줄 배치 캐시)를 지운다. 표 칸을 고치면 그 표를 품은 본문 문단의 캐시까지 지운다.
- 단위 HWPUNIT: 1pt = 100, 1mm ≈ 283.46. A4 본문 폭(여백 30mm) 42520.

## 한글 판에 따른 차이

- **문단 여백이 두 배로 저장된다.** 한글 2022 이후가 저장한 파일은 `hp:switch` > `hp:case`에 실제 값, `hp:default`에 두 배 값을 함께 둔다. 한컴 2020이 저장한 파일은 switch 없이 **두 배 값만** 둔다(실제 3pt 왼쪽 여백 → 600). `hwpx_lib.para_margins()`가 둘 다 실제 값으로 돌려준다.
- 한컴이 다시 저장하면 header의 id 번호·스타일 참조가 정리될 수 있다. 다음 단계 스크립트는 **한컴이 저장한 파일을 바탕으로** id를 다시 찾는다(이전 단계 id를 외워 두지 않는다).

## 한컴 자동화(COM)

- `win32com.client.DispatchEx('HWPFrame.HwpObject')`. 새 Hwp.exe가 생겼는지 프로세스 목록으로 확인한다. 안 생겼으면 사용자 한컴에 붙은 것 → 즉시 멈춘다.
- 창 숨기기 `hwp.XHwpWindows.Item(0).Visible = False`, 대화상자 기본 응답 `hwp.SetMessageBoxMode(0x00011111)`(확인·예 등을 자동으로 고름), 열기 `hwp.Open(path, 'HWPX', 'forceopen:true')`, 저장 `hwp.SaveAs(path, 'HWPX'|'PDF', '')`, 끝 `hwp.Clear(1); hwp.Quit()`.
- 보안 창 '…파일에 접근하려는 시도'는 WPF라 BM_CLICK·UIA Invoke가 듣지 않는다. 실제 마우스 커서가 그 창 위에 있을 때만 보낸 클릭을 받는다 → 창을 **커서 밑으로 옮기고(활성화 없이)** WM_LBUTTONDOWN/UP를 보낸다(`hwp_allow.ps1`).
- '차례 만들기'(MakeContents)를 자동화로 부르면 제목 차례를 모을 때 한컴 2020이 죽는다('서버에서 예외 오류'). 표·그림 차례는 된다. 목차는 그 기능이 만드는 모양대로 두고 번호만 PDF에서 읽어 넣는다.
- 한 번 렌더(60쪽)에 60~90초.

## 글자 폭(PDF에서 잰 값, 함초롬돋움 11pt)

- 한글 0.97em, 숫자 0.55em, '(' 0.305em, 장평 60% '−' 0.58em. **빈칸은 0.5em**(글꼴 파일은 0.3em이지만 한컴은 넓게 놓는다). 쉼표는 0.5em으로 잡으면 안전.
- 표 칸 폭 계산: 칸 너비 − 칸 좌우 여백 − **문단 왼쪽 여백(왼쪽 정렬 칸은 3pt=300이 흔함)**. 여유 계수 1.04~1.06을 곱한다.
- 돋움체(고정폭, gulim.ttc index 3): ASCII 0.5em, 한글 1em. 9.5pt에서 칸 안쪽 40934 → 86칸.

## 표

- 칸보다 긴 줄은 한컴이 **낱말 중간에서** 끊는다(어절 단위 설정이어도). 줄을 `hp:lineBreak`로 직접 나누고 열 너비를 가장 긴 낱말 이상으로.
- 본문 폭 42520짜리 표에 바깥 여백 283이 있으면 한컴이 마지막 열을 줄인다 → 표 너비 41952(= 42520 − 283×2)로.
- `cellSz height`는 **최소 높이**다. 줄 수에 맞춘 높이 = 칸 위아래 여백 합 + 줄 높이×줄 수(11pt·줄 간격 115%: 284 + 1265×n; 10.5pt: 284 + 1206×n). 글을 줄이고 옛 높이를 두면 칸이 비어 보인다 → 여백 합(최소값)으로 낮추면 한컴이 맞춘다.
- 여러 쪽 표: `repeatHeader="1"`(제목 행 반복), `pageBreak="TABLE"`(셀 단위로 나눔, 행이 통째로 넘어감). `CELL`이면 한 행이 두 쪽에 갈린다.
- 표 번호를 바꾸면 '[표 7]는' 같은 조사 오류가 생긴다 → `josa()`.

## 쪽 나눔·캡션

- 제목+설명이 앞 쪽, 표가 다음 쪽 → 설명 문단에 '다음 문단과 함께'(keepWithNext). 사이 빈 문단도 켜져 있어야 이어진다.
- 한 쪽을 거의 채우는 상자 앞 문단에 keepWithNext를 걸면 상자는 그대로 두고 **캡션만** 다음 쪽으로 밀릴 수 있다. 상자를 줄이는 것(줄 간격 180→160%, 글자)이 낫다.
- 캡션 문단 모양: 아래 '주:'가 붙는 캡션은 아래 간격이 작게(200), 보통 캡션은 크게(1200) 되어 있는 경우가 많다. 주를 각주로 옮기면 캡션 모양도 보통 것으로.
- 큰 표 둘을 한 쪽에: 표 사이 쪽 나눔을 없애고, 표 행 높이를 줄 수에 맞추면 들어가는 경우가 많다.

## 글꼴

- 문서가 쓰는 글꼴이 PC에 없으면 한컴은 조용히 다른 글꼴로 PDF를 만든다. `render.py`가 미리 경고한다. PDF의 글꼴 목록(`PDF fonts:`)도 확인한다.
- 한컴오피스는 자기 글꼴 일부(한컴바탕 등)를 Windows에 등록하지 않고 `Program Files (x86)\Hnc\Office 20xx\HOffice1xx\Shared\TTF\…`에 둔다. Windows 글꼴 목록에는 없어도 한컴은 쓴다(PDF에 'Haansoft Batang'으로 들어감). 받는 사람도 한컴이 있으면 같게 보인다.
- 사용자 글꼴(%LOCALAPPDATA%\Microsoft\Windows\Fonts + HKCU 등록)은 **다시 로그인하면 목록에서 빠져 있을 때가 있다**(파일·레지스트리는 남음; 11-16, 11-20에 두 번 겪음). `render.py`가 렌더 전에 AddFontResource로 다시 올린다. 손으로는 `fonts.ps1 -Reload`.
- KoPub 글꼴은 한국출판인회의(kopus.org) 배포. 고정폭 한글 글꼴은 Windows 기본 돋움체·굴림체(어느 PC에나 있어 받는 사람 쪽에서도 같게 보임).
- matplotlib 그림에 한글 글꼴 굵기를 고르려면 굵기별로 이름을 바꾼 사본이 필요했다(가족 이름으로는 굵기를 못 고름).

## 작업 습관

- 고치기 전 백업, 원본 위에 덮어쓰지 않기, 최종본은 한컴 재저장본.
- 스크립트는 단계마다 한 파일(`apply_<판>.py <바탕> <출력>`)로 남겨 다시 돌릴 수 있게. 찾기는 항상 '정확히 하나' assert.
- 오래 걸리는 탐색(열 너비 전수 조사 등)은 조합 수를 먼저 계산한다. 열 7개를 200 단위로 전수 조사하면 끝나지 않는다(4개 이하만 전수, 그 이상은 탐욕+동점 깨기).
- 피드백 원문은 서식(굵게=중요, 취소선=이미 됨)까지 읽어 기록 파일에 옮기고, 항목마다 반영/미반영과 근거를 수정 대조표에 남긴다.
- 피드백이 제시한 문장도 문서의 수치와 맞는지 확인한 뒤 넣는다.
- 웹 채팅에 파일을 올릴 때 메시지 하나에 파일 하나만 붙는 서비스가 있다(Google Chat). hwpx와 pdf를 따로 보낸다.
